# H2 1.4.200 → 2.4.240 Migration — Failure-Mode Catalog and Hardening Plan

## Context

Semoss is migrating all customer H2 databases from 1.4.200 → 2.4.240 to remediate the four CVEs noted in the utility README. The existing utility at [h2-update-utility/](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/) works for our green-path test fixtures, but real customer databases contain schema shapes the tests do not cover. We have already seen at least one failure in the wild (`Unknown data type: "DATETIME"`) and need a systematic understanding of every other way the migration can fail — both to document it for our field team and to decide which defenses to bake into the utility before wider rollout.

The utility today is minimal by design: for each DB it runs `SCRIPT TO` under H2 1.4.200 (read-only), then `RUNSCRIPT FROM '…' FROM_1X` under H2 2.4.240, with no custom SQL rewriting and **no compatibility flags on the target connection**. Every migration incompatibility not handled by H2's built-in `FROM_1X` flag surfaces as a hard failure, rolls back the backup, and reports only `SQLException.getMessage()`.

## Current behavior — one-line summary of key files

- [DatabaseExporter.java:43](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/DatabaseExporter.java#L43) — old-DB URL: `jdbc:h2:<path>;ACCESS_MODE_DATA=r` (no other flags).
- [DatabaseExporter.java:50](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/DatabaseExporter.java#L50) — `SCRIPT TO '<path>'` (no options like `NODATA`, `NOPASSWORDS`, `SIMPLE`).
- [DatabaseImporter.java:49](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/DatabaseImporter.java#L49) — `RUNSCRIPT FROM '<path>' FROM_1X` against `jdbc:h2:<path>` with **no** `MODE=`, `NON_KEYWORDS=`, `DEFAULT_NULL_ORDERING=`, `DATABASE_TO_UPPER=` flags on the target URL.
- [H2MigrationService.java:229-246](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/H2MigrationService.java#L229-L246) — on import failure: restore backup, record `e.getMessage()`, move on. No statement-level context, no line number, no remediation hint.
- No pre-flight script validator. No SQL rewriter. No custom-alias re-registration (SMSS_MEDIAN on the target is never re-verified).

## Categorized failure modes

Each entry: **pattern → error message the customer sees → what triggers it → recommended defense**. "FROM_1X handles" is noted where true; everything else is a real risk today.

### Category A — Removed/renamed data types (FROM_1X handles most, not all) ✅ COMPLETED

Addressed by [ScriptRewriter.java](src/main/java/org/semoss/h2/migration/ScriptRewriter.java), invoked from [H2MigrationService.java](src/main/java/org/semoss/h2/migration/H2MigrationService.java) between export and import for both local and cloud modes. The rewriter processes the SCRIPT dump line-by-line, skipping single-quoted strings and double-quoted identifiers, and applies the type-alias replacements listed below with case-insensitive word-boundary matching. Replacements: `DATETIME → TIMESTAMP`, `LONGVARCHAR → VARCHAR`, `LONGVARBINARY → VARBINARY`, `LONGTEXT → CLOB`, `MEDIUMTEXT/TINYTEXT/NTEXT → VARCHAR`, `MEDIUMBLOB/TINYBLOB → BLOB`, `NUMBER → NUMERIC`, `IDENTITY (as column type) → BIGINT GENERATED BY DEFAULT AS IDENTITY` (function call `IDENTITY(...)` is left alone via negative look-ahead). A `.pre-rewrite.bak` sibling is created when replacements are applied for post-mortem analysis and cleaned up after successful import. Covered by 20 unit tests in [ScriptRewriterTest.java](src/test/java/org/semoss/h2/migration/ScriptRewriterTest.java), including an end-to-end test that confirms the raw script fails under H2 2.4.240 but the rewritten script imports and queries cleanly.


| Old (1.x) | New (2.x) | Error | Handled by FROM_1X? |
|---|---|---|---|
| `DATETIME` | `TIMESTAMP` | `Unknown data type: "DATETIME"` | ❌ **confirmed failing in the wild** |
| `LONGVARCHAR` | `VARCHAR`/`CLOB` | `Unknown data type: "LONGVARCHAR"` | ❌ |
| `LONGVARBINARY` | `VARBINARY`/`BLOB` | `Unknown data type: "LONGVARBINARY"` | ❌ |
| `IDENTITY` (as a type) | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | `Unknown data type: "IDENTITY"` | ❌ |
| `NUMBER` | `NUMERIC` (or `MODE=Oracle`) | `Unknown data type: "NUMBER"` | ❌ |
| `TINYTEXT`/`MEDIUMTEXT`/`NTEXT` | `VARCHAR`/`CLOB` | `Unknown data type: ...` | ❌ |
| `ENUM` | `ENUM(...)` with 1-based ordinals | ordinal-off-by-one at runtime | Partial |
| `BINARY` (no length) | fixed-length default 1 | silent truncation to 1 byte | ❌ |

**Defense**: add a pre-import SQL rewriter that regex-replaces these aliases in the exported script. Even if Semoss itself does not emit `DATETIME` today (we verified — [AnsiSqlQueryUtil.java:806](../../Documents/SEMOSS/workspace/Semoss/src/prerna/util/sql/AnsiSqlQueryUtil.java#L806) returns `TIMESTAMP`), customer-uploaded DBs and older Semoss versions did.

### Category B — New reserved keywords as column/table names

H2 2.x promoted many identifiers to reserved keywords: `VALUE`, `KEY`, `TOP`, `ROW`, `RANGE`, `INTERSECTS`, `WINDOW`, `OFFSET`, `FETCH`, `SESSION_USER`, `LOCALTIME`, `LOCALTIMESTAMP`, `CURRENT_CATALOG`, `CURRENT_PATH`, `DAY`/`MONTH`/`YEAR`/`HOUR`/`MINUTE`/`SECOND`, `_ROWID_`.

Semoss dynamic-upload path *does* sanitize (see [HeadersException.java](../../Documents/SEMOSS/workspace/Semoss/src/prerna/util/HeadersException.java)) but via a **deny-list loaded from a properties file**, which may be out of date with H2 2.x. Plus customer-uploaded DBs from earlier Semoss versions can contain any of these as columns.

**Error**: `Syntax error in SQL statement "… CREATE TABLE FOO(VALUE VARCHAR …" expected identifier`.

**Defense**: open the target URL with `;NON_KEYWORDS=VALUE,KEY,TOP,ROW,RANGE,INTERSECTS,WINDOW,OFFSET,FETCH,SESSION_USER,LOCALTIME,LOCALTIMESTAMP,DAY,MONTH,YEAR,HOUR,MINUTE,SECOND,CURRENT_CATALOG,CURRENT_PATH`. Note: `ROW` cannot be suppressed via `NON_KEYWORDS` (upstream issue #3390) — if any column is literally named `ROW`, we must rewrite it in the script or fail loudly.

### Category C — Custom aggregate `SMSS_MEDIAN`

[H2QueryUtil.java:162](../../Documents/SEMOSS/workspace/Semoss/src/prerna/util/sql/H2QueryUtil.java#L162) registers `CREATE AGGREGATE IF NOT EXISTS SMSS_MEDIAN FOR "prerna.ds.rdbms.h2.H2MedianAggregation"`. `SCRIPT TO` will emit this into the dump. At `RUNSCRIPT FROM … FROM_1X` time the utility's classloader parent is the platform classloader ([IsolatedH2Driver.java:67](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/IsolatedH2Driver.java#L67)) which does **not** contain the Semoss classpath. H2 resolves the aggregate class lazily (at invocation, not at CREATE), so the CREATE itself usually succeeds — but we have never tested this, and H2 2.x may have tightened validation.

**Defense**: add an integration test that exports a DB containing `SMSS_MEDIAN`, imports it, and re-opens it under a classloader that has `H2MedianAggregation` available. If validation is eager in 2.x, strip the `CREATE AGGREGATE` line before import and re-add it post-migration.

### Category D — `CHECK` constraints and views using 1.x-only expressions

FROM_1X runs the 1.x grammar for DDL statements but the resulting CHECK expression is re-parsed against the 2.x grammar at insert time. Patterns that survive migration but break later:
- `CHECK (flag = 1)` where `flag` is `BOOLEAN` — 2.x rejects int-vs-bool comparison.
- `CHECK (len(name) > 0)` — `len` vs `length` dialect drift.
- Views containing `GROUP_CONCAT(... SEPARATOR ',')`, `CASEWHEN(...)` — both removed; 2.x only has `LISTAGG` / `CASE WHEN`.

Semoss system DBs do not emit these, but Quartz schema and user-loaded DBs might. Mitigation: `MODE=LEGACY` restores `GROUP_CONCAT` and `CASEWHEN`, and relaxes boolean-vs-int.

### Category E — LOB handling

- `SYSTEM_LOB_STREAM` artifacts in the 1.x dump — `FROM_1X` strips them; verified.
- Very large CLOBs (>100MB single value) — dumped inline as SQL literals. `RUNSCRIPT` reads the whole line into memory. Potential OOM.
- Default LOB size limits and `MAX_LENGTH_INPLACE_LOB` differ between 1.x and 2.x — if a customer explicitly bumped these, migration needs to carry them.

**Defense**: pre-flight report on exported script size per database; warn above threshold; allocate heap via `-Xmx` in launcher.

### Category F — Identity / sequence differences

Semoss hand-assigns IDs; no `INT IDENTITY`/`AUTO_INCREMENT` in system schemas. Quartz uses its own ID generation (no SEQUENCE objects either). Customer DBs might. 2.x requires `GENERATED BY DEFAULT AS IDENTITY`; `CACHE 1` on sequences is rejected (`MODE=LEGACY` does not relax this).

### Category G — PageStore (`.h2.db`) legacy format

H2 2.x cannot open `.h2.db` at all. The utility detects these ([H2VersionDetector.java](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/H2VersionDetector.java)) and routes them through 1.4.200 export → 2.x import, which is correct. **But no integration test exercises a `.h2.db` file**, so this path is unverified. Some early customer deployments predate MVStore.

### Category H — Encrypted databases (`CIPHER=AES`)

Semoss does not use CIPHER-encrypted H2, but customers occasionally enable it. Current utility reads only `USERNAME`/`PASSWORD` from the `.smss`, not `CIPHER=AES` or the cipher password. An encrypted DB silently fails export with a confusing `File corrupted` or `Wrong password` error. Needs detection + clear error.

### Category I — Connection URL flags deprecated in 2.x

Semoss connection strings ([Constants.java:653](../../Documents/SEMOSS/workspace/Semoss/src/prerna/util/Constants.java#L653), [H2QueryUtil.java:113](../../Documents/SEMOSS/workspace/Semoss/src/prerna/util/sql/H2QueryUtil.java#L113)) use `query_timeout`, `early_filter`, `query_cache_size`, `cache_size`, `LOCK_MODE=1`. H2 2.x removed `MVCC`, `MV_STORE=false`, `CACHE_TYPE`, `LOG=0` — none of which Semoss uses, so this is safe. But any *customer* `.smss` with a custom `CONNECTION_URL` may contain removed flags, which breaks the first post-migration open (not the migration itself).

**Defense**: after successful migration, open the new DB once with the SMSS-derived URL as a smoke test; fail the migration if the post-migration open fails, so it's caught in the migration run rather than later by Semoss.

### Category J — `MERGE INTO … KEY(…)` / `SELECT TOP n` / `CASEWHEN` in runtime queries

[RdbmsQueryBuilder.java:62-72](../../Documents/SEMOSS/workspace/Semoss/src/prerna/ds/util/RdbmsQueryBuilder.java#L62-L72) (deprecated but still called), [AnsiSqlQueryUtil.java:202](../../Documents/SEMOSS/workspace/Semoss/src/prerna/util/sql/AnsiSqlQueryUtil.java#L202) (`GROUP_CONCAT`). These are runtime-only: they fail *after* migration, at Semoss-query time. Not blockers for the migration utility, but field teams need to know.

### Category K — Error reporting limitations (meta-failure)

[H2MigrationService.java:245](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/H2MigrationService.java#L245) captures only `e.getMessage()`. When a 10,000-line script fails on line 7421, the customer gets `Syntax error` with no line number, no statement, no hint. They cannot self-diagnose and support cannot either without asking for the full export file (which is preserved in backup dir, but the report does not surface its path prominently).

### Category L — Coverage gaps in the test suite

The Explore pass found these schema shapes are NOT tested: CREATE VIEW, CREATE TRIGGER, CREATE ALIAS/AGGREGATE (including `SMSS_MEDIAN`), CREATE SEQUENCE, CHECK constraints, reserved-word identifiers, `.h2.db` PageStore round-trip, large (>100MB) CLOBs, self-referencing FKs, Windows path escaping. See [LocalMigrationIT.java](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/test/java/org/semoss/h2/migration/LocalMigrationIT.java) for the current surface.

## Recommended hardening plan (prioritized)

### P0 — Must ship before broader customer rollout

1. **Target-connection compatibility flags.** Modify [DatabaseImporter.java:45-49](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/DatabaseImporter.java#L45-L49) to build the target URL as:
   ```
   jdbc:h2:<path>;MODE=LEGACY;NON_KEYWORDS=VALUE,KEY,TOP,RANGE,INTERSECTS,WINDOW,OFFSET,FETCH,SESSION_USER,LOCALTIME,LOCALTIMESTAMP,DAY,MONTH,YEAR,HOUR,MINUTE,SECOND,CURRENT_CATALOG,CURRENT_PATH;DEFAULT_NULL_ORDERING=LOW;DATABASE_TO_UPPER=TRUE
   ```
   `MODE=LEGACY` single-handedly covers GROUP_CONCAT, CASEWHEN, boolean/int flex, MERGE…KEY, IDENTITY-as-type, and AUTO_INCREMENT. It's the single highest-leverage change.

2. **Type-alias rewriter between export and import.** Add `ScriptRewriter.java` next to `DatabaseExporter` that reads the script line-by-line and rewrites, outside quoted strings, just: `DATETIME` → `TIMESTAMP`, `LONGVARCHAR` → `VARCHAR`, `LONGVARBINARY` → `VARBINARY`, and `IDENTITY` → `BIGINT GENERATED BY DEFAULT AS IDENTITY` when used as a column-type token. Invoked in [H2MigrationService.java](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/H2MigrationService.java) between the export step and the import step.

3. **Better failure reporting.** Extend [MigrationReport.java](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/MigrationReport.java) and the failure path in [H2MigrationService.java:229-246](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/main/java/org/semoss/h2/migration/H2MigrationService.java#L229-L246) to also record: (a) the absolute path of the preserved export script in the backup dir, (b) the SQLException class + SQLState + ErrorCode, (c) if H2's message includes `Syntax error in SQL statement "…"`, extract that quoted fragment into its own `failingStatement` field. This is a small change with outsized support value.

4. **Post-migration smoke open.** After RUNSCRIPT succeeds, close the target, then reopen with the Semoss-style URL (read from the companion `.smss` if present, else default) and run `SELECT 1`. If this fails, treat migration as failed and restore the backup. Catches Category I issues immediately.

5. **Integration tests for the currently-untested shapes.** Add fixtures to [src/test/](../../Documents/SEMOSS/workspace/h2-upgrade/h2-update-utility/src/test/) covering:
   - A table with columns named `VALUE`, `KEY`, `TOP`, `YEAR` (Category B).
   - A DB containing `CREATE AGGREGATE SMSS_MEDIAN …` (Category C).
   - A `.h2.db` PageStore fixture (Category G).
   - A `DATETIME` / `LONGVARCHAR` fixture (Category A — regression guard for the customer-reported failure).
   - One `MODE=LEGACY`-dependent pattern (GROUP_CONCAT inside a VIEW).

### P1 — High value, next iteration

6. **Pre-flight script scanner.** After export, before import, scan the SQL text and produce a list of "high-risk patterns detected" in `MigrationReport.databases[i].warnings[]` (e.g. `"contains CREATE AGGREGATE referencing prerna.ds.rdbms.h2.H2MedianAggregation"`, `"contains CREATE TRIGGER"`, `"contains identifier 'ROW' which cannot be suppressed"`). Non-blocking — pure observability.

7. **Encrypted DB detection (Category H).** If the 1.x open fails with `file corrupted` or `wrong user name or password`, probe the `.mv.db` header bytes for the cipher signature and emit a clear error: `"Database appears to be CIPHER-encrypted. Utility does not support encrypted H2 migration; decrypt first."`.

8. **Heap-pressure warning for large LOB dumps.** Log the exported script size and compare against JVM max heap; print a warning if script > 50% of heap.

### P2 — Defense-in-depth

9. **Per-statement RUNSCRIPT mode.** Alternative import path that reads statements one at a time and executes them individually, so on failure we know the exact offending statement and can continue-past-error in report-only mode.

10. **Known-keyword auto-discovery.** Before opening the target, regex-scan identifiers in the script and compare against the full H2 2.x reserved-word set; pass *only* the ones actually present as `NON_KEYWORDS=…` rather than a static list.

## Out of scope for this plan

- Rewriting Semoss runtime queries to remove `MERGE INTO … KEY`, `GROUP_CONCAT`, `CASEWHEN`, `PARSEDATETIME`/`FORMATDATETIME`. Those are Category J — Semoss-side fixes, handled by the H2 2.x Semoss branch, not by the migration utility.
- OWL sidecar regeneration. Column types are preserved through migration, so OWL stays valid.
- Cloud-mode-specific behavior. All hardening lives in the Export → Rewrite → Import core; it benefits both local and cloud paths unchanged.
